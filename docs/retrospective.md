## 원정린

### 좋았던 점

팀 프로젝트를 통해 브랜치와 PR을 활용한 Git/GitHub 협업을 제대로 경험하며, 전반적인 Git 이해도를 크게 높일 수 있었다.

### 아쉬웠던 점

마음이 급해 구조를 꼼꼼히 잡지 않고 시작했다. CSS의 `:root`를 활용하지 못했고, 중복 코드도 많았다. 일정이 촉박해 중간 점검 없이 각자 작업한 뒤 마지막에 하나로 합쳐 제출했다.

개인 사정으로 최종 시연과 발표까지 참여하지 못했다. 팀의 전체 완성본과 작업 흐름을 온전히 확인하지 못해 더 많은 부분을 놓친 느낌이 들었다.

### 배운 점과 다짐

구현 속도에 앞서 구조를 섬세하게 설계하고, `:root`로 공통 스타일을 먼저 잡는 것의 중요성을 배웠다. 일정이 촉박할수록 각자 작업한 것을 마지막에 합치기보다, 중간중간 함께 점검하고 진행 상황을 맞추는 과정이 필요하다고 느꼈다.

## 장예지

### 좋았던 점

개발자 도구(F12)로 실제 서비스의 HTML/CSS를 직접 열어보며 구조를 읽는 연습을 할 수 있었다. 디자인을 보는 것보다 그 뒤의 레이아웃 구조를 파악하는 것이 훨씬 중요하다는 점을 이해했다.

평소 터미널 명령어로 익히던 Git/GitHub 작업을 이번에는 Fork 기반의 GUI 흐름으로 경험했다. 협업 도구로서 Git/GitHub를 사용하는 방법을 직접 익힐 수 있는 시간이었다.

### 아쉬웠던 점

- 일단 되게만 만들고 넘어간 부분이 많았다.
- 팀 논의가 필요한 사항들을 결정하지 못한 채 넘어간 경우가 많았다.
- 참고 디자인과의 격차를 단순화라는 말로 정리하고 넘어간 경우가 있었다.
- 코드 중간에 남은 실수와 작업 흔적을 충분히 정리하지 못했다.
- 역할은 나눴지만 코드를 형상 관리하는 데 그쳤고, 구현 과정에서 발견한 내용은 공유하지 못했다.
- 과제를 수행할 시간이 절대적으로 부족했다.

HTML/CSS 기초 과정을 끝낸 지 하루 만에 프로젝트를 수행하다 보니, 필요한 키워드를 찾는 것부터 어려웠다. 개념을 충분히 이해하고 적용할 여유가 부족했다.

## 김민지

### 어려웠던 점과 해결 과정

처음에는 페이지를 어떻게 나누어야 할지 감이 오지 않았다. 개발자 도구를 봐도 어느 범위를 `section`으로 잡고, 그 안을 어떻게 `div`로 나누어야 할지 알기 어려웠다. 팀원이 큰 영역을 `section`으로 잡고 내부를 `div`로 나누는 예를 보여준 덕분에 구조를 잡을 수 있었다.

클래스가 많아질수록 직접 지은 이름도 헷갈려 많이 헤맸다. 클래스 이름을 짓는 방식을 찾아보고 정리한 뒤에는 혼란이 줄었다.

가장 애먹었던 부분은 여백이었다. 시간이 부족해 여백 개념을 충분히 공부하지 못한 상태에서 코드를 작성하다 보니, 여백이 점점 꼬이는 경우가 있었다. 개념 공부를 더 하지는 못했고, 개발자 도구에서 원본이 어느 요소에 여백을 얼마나 주었는지 확인하며 구현했다.

### 아쉬웠던 점과 다음 연습

담당 페이지에는 사진이 많이 들어가서 겉으로 보기에는 그럴듯했지만, 사진을 빼면 실제로 한 작업이 별로 없다는 느낌이 들었다. 사진이 적은 페이지를 맡은 팀원들은 이미지의 도움 없이 여백과 배치만으로 화면을 만들어야 했을 테니, 오히려 그쪽이 더 어려운 작업이었을 것 같다.

다음에 다시 연습할 때는 이미지가 적은 페이지를 골라보고 싶다. 여백에서도 덜 헤맬 수 있도록 관련 개념을 더 공부할 생각이다.

## 이승주

### 한 줄 요약

Grid와 Flex를 언제 써야 하는지에 대한 원칙은 아직 없다. 대신 맞지 않으면 값을 바꾸고 될 때까지 시도하는 방식으로 반응형 페이지 하나를 완성했다. 우선은 원본과 얼추 비슷하게 만드는 것이 목적이었다.

### Grid와 Flex를 나누어 쓴 방식

명확한 기준보다는 **칸을 나눌 때는 Grid, 한 줄로 정렬할 때는 Flex**라는 손에 익은 방식대로 사용했다.

- `.wrap1 { display: grid; grid-template-columns: 1fr 2fr; }`: 대시보드와 안내 영역을 두 칸으로 나눌 때 Grid를 선택했다.
- `.service-info { display: flex; align-items: center; justify-content: center; }`: 두 정렬 속성이 각각 어느 축을 담당하는지 구분하지 못해, 둘 다 넣어보고 원하는 결과가 나오는 조합을 사용했다.
- `nav > div { width: 768px; display: flex; justify-content: space-between; margin: 0 auto; }`: 메뉴 버튼처럼 한 줄로 나열하는 곳에는 Flex를 사용했다.

대화 중에 Grid의 기본 정렬이 stretch로 동작해 `.wrap1` 안의 두 `.container` 높이가 맞춰진다는 설명을 들었다. 반대로 `align-items: center`를 넣었다가 높이가 맞지 않는 문제도 겪었다.

### 시행착오 기록

1. `.wrap1`에 `align-items: center`를 넣었다가 두 영역의 높이가 맞지 않았다.
2. `<a>` 안에 `<a>`를 중첩하려다 막혀, `<span>`과 JavaScript의 `onclick`으로 우회했다.
3. `margin: 10px` 하나로 의도하지 않은 들여쓰기가 생겼다.
4. hover 시 부모만 바뀌고 자식의 색은 바뀌지 않았다. `.container:hover .subtext`처럼 자식 요소를 직접 지정했다.
5. FAQ 카드 중 하나에만 제목이 없어 높이가 맞지 않았다. `visibility: hidden`으로 해결했다.
6. nav의 active 밑줄 위치가 nav와 main의 경계선에 맞지 않았다.
7. 그리드 칸마다 테두리를 따로 넣는 방법을 찾지 못해, 겹치는 부분을 배경색으로 덮었다.
8. 768px 브레이크포인트는 계산한 값이 아니라 화면을 좁혀보며 깨지는 지점을 눈으로 확인해 정했다.

### 코드 밖에서 겪은 문제와 미완성 항목

nav의 폰트가 적용되지 않는 문제가 있었다. 광고 차단 확장 프로그램이 jsDelivr CDN을 막았을 가능성을 생각했다.

Git 병합 충돌 후 `git commit`, `git push` 순서로 진행했지만 같은 오류가 반복되어 원인을 명확히 알지 못했다. 햄버거 메뉴 오버레이도 구현하지 못했다.

### 느낀 점

프로젝트에서 발생한 문제는 대부분 개인 역량의 문제라고 느꼈고, 특히 Git에서 많이 막혔다. Grid와 Flex도 시행착오로 밀어붙였기 때문에 제대로 사용했는지는 아직 확신이 없다.

팀원들 모두 초반에는 속도가 느렸지만, 각자 맡은 페이지를 묵묵히 끝까지 책임지고 완성한 점이 인상적이었다. 문제가 생기면 말이 많아지는 편인데, 말을 줄이고 해결에 집중해야겠다고 생각했다. 다른 팀원들의 코드를 살펴보며 나와 다르게 구현한 부분도 찾아보고 싶다.

### 추가로 정리한 해결 계획

Git 오류가 발생했던 상황과 오류 메시지를 기록해 두었다. 기록을 바탕으로 좋지 않은 사용 습관이 있었는지 확인하고, 협업에서 Git을 쓰는 흐름을 익히고 싶다. 협업 기회가 많지 않은 만큼 다음 기회에는 더 주의해서 사용해볼 생각이다.

문제의 원인으로 지목된 OS 설정도 수정했다. 앞으로 같은 오류가 반복되는지 확인하고, 해결되지 않는다면 대처 방법이라도 익혀 이후에 해결 시간을 줄이고 싶다.

HTML/CSS는 당분간 여러 예제와 사례를 직접 구현하면서 감각을 익혀야 할 것 같다. 패턴이 익숙해지면 시행착오도 줄어들지 않을까 생각한다. Figma 같은 도구가 시행착오를 더 줄여줄 수 있을지도 궁금하지만, 지금은 코드를 쓰는 방법부터 익혀야 하는 단계라고 받아들이고 있다.

## 배경일

### 과제 이해와 소통

발표 팀을 정하기 20분 전에야 과제의 요지가 사이트를 그대로 구현하는 데 있다는 것을 깨달아 난처했다. 팀원들과 조금 더 대화했다면 일찍 알 수 있었을 문제라 스스로 아쉬웠다.

### 협업에서 아쉬웠던 점

처음 이야기했던 공용 CSS 파일처럼 협업의 의미를 살릴 수 있는 작업을 더 해봤다면 어땠을까 생각한다. 다만 시간이 촉박했고, 나를 포함한 팀원들도 HTML/CSS로 처음 무언가를 만들다 보니 서로의 작업을 살펴볼 여유가 없었다.

### 결과물을 보며 느낀 점

만드는 동안 스스로 많이 타협했다. 조금 못생겼더라도 외관상 필요한 요소가 들어가 있으면 이 정도로 충분하지 않을까 생각했다.

다른 분들의 결과물을 직접 보고 나니, 피곤하고 머리가 아프다는 이유로 적당히 타협해서 내놓은 내 결과물이 아쉬웠다. 다음 팀 프로젝트에서는 팀원들과 더 많이 이야기하고, 결과물의 완성도를 높이기 위해 스스로 더 노력할 필요가 있다고 느꼈다.
